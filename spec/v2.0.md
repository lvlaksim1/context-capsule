# Context Capsule v2 — Portable Project Manager Model

Status: development design implemented on `v2-manager-runtime`.

## Product definition

Context Capsule v2 is not merely repository-local project memory. It is a portable durable representation of a Project Manager that can be reinstantiated in a new chat, model, process, or agent runtime.

A runtime is an execution carrier. The manager remains the same manager while runtime instances change.

## Manager state model

The active manager state is deliberately separated into:

- **Beliefs** — current factual/inferential model of the project, with provenance and authority.
- **Goals** — desired durable outcomes.
- **Intentions** — accepted commitments that survive runtime replacement.
- **Plans** — current strategy for satisfying intentions.

This is inspired by BDI agent architecture but adapted for repository-native engineering/project management.

## Universal Manager Protocol

Universal professional behavior belongs to Core and is installed as `.context/manager/PROTOCOL.md`. Project-specific authority belongs to `.context/manager/mandate.md`.

The universal loop is:

`Reinstate → Reconcile → Plan → Execute → Verify → Reflect → Persist`

## Stable identity

`.context/manager/identity.json` carries a stable `manager_id`. `manager_id` is repository-scoped and must not be replaced by chat IDs, model names, process IDs, or other runtime identifiers.

## Typed memory

- semantic memory — reusable knowledge and verified lessons;
- episodic memory — selected significant situations where chronology/context matters;
- procedural memory — learned workflows and verification techniques.

Decisions and rules remain first-class durable project surfaces.

## Provenance and memory poisoning boundary

Manager beliefs must preserve source and authority. External content, specialist-agent output, and manager inference are not automatically authoritative. Conflicts remain explicit until resolved; supersession is explicit rather than silent.

## Runtime checkpoint boundary

Context Capsule is not a workflow/checkpoint engine. Conversation history, pending tool calls, hidden reasoning, and transient executor state are runtime state. A runtime may persist its own checkpoint separately. `runtime.checkpoint_is_capsule_state` is permanently `false`.

## Handoff

`handoffs/latest.md` remains available as an emergency/convenience summary. It is no longer a required continuity primitive for `READY`; the manager's durable identity and active state are authoritative.

## Lifecycle

- `install`: creates a v2 structural capsule; initially VALID but normally not READY until manager/project semantics are captured.
- `upgrade`: explicit v1.3.x → v2 transition. It preserves project-owned context and adds manager/memory surfaces. Major upgrade is never hidden inside repair.
- `repair`: operates only within the already-installed v2 major line.
- `ready`: means Project Manager reinstantiation readiness.
- `recover`: emits a deterministic manager reinstantiation pack.

## Compatibility invariant

Stable v1.3.1 remains a valid released product. v2 development must not mutate known consumer repositories or silently upgrade them.
